今日学习计划

今天的学习目标有四个：把 `Tool Runtime` 讲成一个可观测、可控制、可追责的执行层；把 `MCP` 的组合爆炸问题、三个角色和三类能力讲透；把鉴权、越权、返回体积和版本协商这几条安全边界摆清楚；最后，用我自己测出来的数，回答评估里最难的那个问题——改完到底有没有用。涉及的术语我会用反引号括起来，重点结论加粗。

上一篇《Agent Day2：Tool Use 学习（上）》已经把调用流程、幂等、错误处理和 `Tool Registry` 四域架构过了一遍，那是"怎么调、调错了怎么办"。这一篇不重复那些，只往上走一层——讲工具从"能被模型选中"到"能在生产里被安全、可控、可验证地反复调用"，中间到底缺了什么。

## Tool Runtime

**问题：模型输出的只是意图，不是执行。**

我一开始想的是，工具调用嘛，模型吐一段 `JSON`，我按名字分发到对应函数就完了。真到生产里才发现，**模型输出的是调用意图，不是执行本身**。执行这件事一旦散落在各处的业务函数里，就同时冒出几个没人管的问题：这个 Agent 有没有权限调它、返回的数据会不会把上下文撑爆、出事之后查不查得到是谁调的传了什么。上一篇讲的幂等和错误处理，解决的是"调错了怎么办"；但"调之前谁来把关、调之后谁来收口"，是另一层。

**我试过的错：只做分发，不做治理。**

最早我把执行直接写在业务函数里，调用、返回、日志各写各的。结果一个查询返回 200 条记录——这是我踩过的真实坑——直接把上下文撑爆，后面几轮推理全乱了。更麻烦的是审计：出了事我答不出"当时模型看到的是什么、传了什么参数"。我当时想的是"先跑起来再说"，后来才明白，跑起来只是第一步，能收住才是本事。

**最后的做法：把执行收口成一个 Runtime。**

`Tool Runtime` 的职责，是把一次调用变成一次**可观测、可控制、可追责**的操作。它不是一个简单分发函数，而是一段固定的收口逻辑：白名单、`JSON Schema` 加业务规则的双层校验、鉴权、幂等检查、带超时和限流的执行、结果裁剪、审计。这几步里，幂等和错误处理上一篇已经讲过，这里不重复；真正值得单说的是结果裁剪和审计。

**结果裁剪是最容易被忽略的一环。** 我的原则是"回填给模型的是它做判断需要的最小集"，不是原始数据。三种裁法各有场景：列表类保留前若干条并标注"还有多少条"；结构化数据只留模型需要的字段；长文本先用小模型摘要再回填。审计则把输入输出、耗时、`token` 全记下来，出了问题能按 `traceId` 回放。这两件事做完，工具调用才从"能跑"变成"能交付"。

## MCP

**问题：M 个模型乘 N 个工具，会变成 M×N 套适配。**

`MCP`（`Model Context Protocol`）解决的不是"怎么调一个工具"，而是"怎么让一套工具被多个宿主复用"。我算过这笔账：M 个模型接 N 个工具，没有协议就是 M×N 套适配；有了 `MCP`，变成 M+N。**这就是它最核心的价值——把组合爆炸按平。**

**三个角色，三类能力。**

`MCP` 里有三个角色，分清楚就不乱：`Host` 是宿主应用，管理连接、决定哪些能力暴露给模型、做权限和确认；`Client` 是 `Host` 内部的连接器，和某个 `Server` 一对一通信；`Server` 是能力提供方，也就是你的业务系统。能力分三类，既高频也最能指导设计：`Tools` 是有副作用的动作，由模型决定调用；`Resources` 是只读数据，由应用或用户选择挂载；`Prompts` 是预置的提示模板，由用户显式选择。**记法很简单：Tools 是"做"，Resources 是"看"，Prompts 是"问的模板"。**

传输上，本地用 `stdio`，宿主直接拉起子进程，最省事；远程这条线，主流已经从 `HTTP` 加 `SSE` 迁到 `Streamable HTTP`。我当时纠结过要不要一上来就上远程，后来定了本地先用 `stdio`——先跑通，再谈分布式。

**我试过的错：把工具一股脑全塞进去。**

工具数量是个隐形杀手。经验上超过 15 个左右，模型选错的概率就会上升——这里说的是经验阈值，不是我的实测值。我现在 `ASC` 的 `MCP Server` 对外 15 个工具，其中 11 个是原版、4 个是端到端测试时新加的；这个数已经贴着经验阈值了，所以分组和检索召回是我下一步要做的事，不是现在已经解决了的。

**最后的做法：治理点放在 Server 侧。**

`MCP` 是能力描述协议，不是传输，更不是鉴权。有四个治理点是我心里"做过"和"读过文档"的分界线：工具描述里同样要写"什么时候不用"，否则模型会乱调；`Server` 侧必须自己做鉴权，`Host` 传过来的身份不能盲信；返回体积要控，`MCP` 没有强制的大小限制，一个 `resource` 返回过大就会打死上下文；版本和能力协商要在 `initialize` 阶段交换清楚，升级时兼容旧 `Client`，否则用户端会集体连不上。**协议标准化的是能力描述，安全和体积这两件事它不管，只能自己在 `Server` 侧兜住。**

## 安全

**问题：安全不在模型那一侧，在执行和协议这一侧。**

工具能被调用，就意味着有副作用、有数据、有权限。`MCP` 那一节其实已经埋了安全的引子，这里单独拎出来讲，是因为它是我踩坑最疼的一块。

**我试过的错：信了上游传来的身份。**

早期我图省事，`Server` 直接信任 `Host` 传来的用户身份，结果越权调用一路畅通。我当时想的是"身份在网关那层已经验过了"，后来才明白：**跨系统传来的身份只能当线索，不能当凭证**。还有一次，一个查询接口没做返回体积控制，返回内容直接把上下文撑爆——前面说过，治理这件事必须自己兜，不能指望协议替你兜。

**最后的做法：四道边界。**

第一道是鉴权，`Server` 侧独立校验令牌和租户，跨租户统一返回不存在，防止被探测。第二道是越权控制，白名单加数据范围，让每个 Agent 只能碰到它该碰的工具和数据——这一步和 `Tool Runtime` 的白名单是同一个思路，只是落到了协议层。第三道是返回体积，截断、字段裁剪、摘要三招，和 Runtime 的结果裁剪共用一套机制。第四道是版本协商，`initialize` 阶段交换协议版本与能力，升级时保留旧 `Client` 的兼容周期。**安全不是一个开关，是四道各管一段的边界；任何一道偷懒，都会变成越权，或者把上下文打爆。**

## 评估

**问题：不能评测的优化都是猜测。**

改完一版，试三个 case，觉得好了——这件事我干过很多次，直到有人问我"你到底提升了多少"，我答不上来。原因很简单：那几个 case 是我自己挑的，我甚至隐约知道怎么问才能让它答对。

**我试过的错：拿手测当回归。**

错在三点：例子是自己挑的，过拟合到自己；只看最终答案对不对，看不到过程里同一个工具用相同参数调了三次、`token` 悄悄翻倍；直接用真实模型跑回归，不可复现还贵——同样输入两次结果不同，改动之后分数变了，你分不清是机制的功劳还是模型的心情。**想测方案，就得先把模型的随机性按住。**

**最后的做法：先定住变量，再上真模型。**

我用规则决策器 `MockAgent` 换掉真实模型做确定性仿真：同样的输入永远给同样的输出，行为按脚本走。这样任何分数变化都只能来自我改的那一层。对照设计上守唯一变量：模型版本锁死、温度设 0、同一批样本、同一个判分器，做 `A/B` 加 `Baseline`，必要时加 `A/B/C` 和消融，看哪个机制真起作用；每个场景重复 N≥5 次，报均值和方差。判分能用规则的用规则，规则类指标占大头，内容质量才用模型当裁判，而裁判要先拿 50 条人工标注集校准过。

数字我给两组，都带口径：

**`ASC` 的确定性仿真**——3 个场景、`MockAgent` 隔离模型变量、组间唯一差异是注入内容：每轮注入 `token` 从 161 降到 47（−70.8%），关键约束违反率从 33.3% 降到 0，重复工具调用从 3 降到 0，跨会话恢复步数从 2 降到 1，两组任务完成率都是 100%。我还加了一组"无限窗口"对照——不裁剪、全量给、换更长窗口，`token` 仍从 147 降到 47（−68.0%），这就排除了"只是截断了历史"这个解释。注意，33.3% 就是三次里错一次，这组数只是下限验证，样本量不足以支撑统计推断。

**`ContextFS` 的确定性下限验证**——固定语料、哈希嵌入：同一命中集合下注入 `token` 128.7 对 1002.8（−87.2%），`recall@3` 为 1.0 持平。

**完成率持平这条最值得说**：省 `token` 最容易的做法是少给信息，但那会掉正确率；完成率不变、`token` 从 161 降到 47，才证明是提效，而不是偷工减料。

### 边界

这套东西有几处我要主动说清。第一，仿真的分数不能对客户讲成端到端提升，它是下限验证；真实模型的端到端评测还在做，目前只定了实验设计——同模型、温度 0、结构化决策输出、规则判分、每场景 N≥5。第二，短任务、单线程、没有交接的场景，为了工具和状态加这一整套治理，是纯开销。第三，评测集会过拟合，一周不更新就开始给你假的好消息，得把真实 bad case 每周回补进去。第四，工具数量一多，分组和检索本身又引入新的复杂度和调试成本，这不是免费的。

这套东西在你那儿大概率不成立的地方是 X，欢迎说说你的场景。下一篇我把工具、状态、评测这三层收成一张图，讲清楚它们各自管什么、不管什么。
