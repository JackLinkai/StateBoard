# Tool Use 推文生成：WorkBuddy 接入 ASC 对照实验

## 一、实验目的

回答一个具体问题：**同一个写作任务，WorkBuddy 不接 ASC 和接 ASC，产物差在哪。**

任务本身：根据本地相关文件，写一篇 Tool Use 主题的公众号推文《Agent Day2：Tool Use 学习（下）——Tool Runtime、MCP、安全与评估》，要求首行是「今日学习计划」正文、四个主题作一级标题、术语用反引号、重点加粗、2500–3500 字、衔接上一篇、不出现编程语言名与旧值。

## 二、环境

| 项 | 值 |
|---|---|
| ASC 服务 | `http://localhost:8080`，健康 `UP` |
| PostgreSQL | 由 `.env` 的 `ASC_DB_URL` 指定（不入库） |
| Redis | 由 `.env` 的 `ASC_REDIS_HOST` / `ASC_REDIS_PORT` 指定 |
| 启动命令 | `cd StateBoard && mvn spring-boot:run` |
| 状态任务 | `tooluse-article-day2`，真实写入 PG/Redis |

> 对外发布说明：历史产物中的本机内网地址与绝对路径已统一脱敏（地址改由 `.env` 变量描述、路径改相对路径或占位符），实验变量、状态卡内容与判分数据未改动。

注意：如果之前用 `-Dspring-boot.run.profiles=local` 起过 H2 模式，必须先停掉再用不带 profile 的命令启动，否则读不到 `.env` 的真实库。

## 三、分组设计

三组**任务描述、素材路径、输出要求完全相同**，唯一差异是注入的上下文包。

| 组 | 上下文包 | 模拟的场景 |
|---|---|---|
| A | 只有任务书和 5 个素材路径 | WorkBuddy 未接入 ASC |
| B | 任务书 + ASC `lean` 状态卡（362 token），含 8 条硬约束、13 条带来源的已确认事实、7 条待办；过期事实被治理层移出 lean | WorkBuddy 接入 ASC，每轮决策前编译注入 |
| C | 与 B 等量事实（约 10.0k 字符 vs B 的 9.7k），但硬约束降为软约束、过期旧值当有效事实并列注入 | 接入了，但治理关掉的消融对照 |

素材里的冲突真实存在，不是编造的噪音：某索引文件引用了旧版材料、某工具笔记写的是旧的工具数量口径、某份经历材料里有含编程语言名的旧账号名。

## 四、执行步骤

```bash
cd StateBoard

# 1. 写入 ASC 任务，导出三组冻结上下文包
python e2e_article/setup_state.py

# 2. C 组重建为等量事实的降级包（只在需要重做消融时跑）
python e2e_article/make_c.py

# 3. 开三个独立 WorkBuddy 会话，分别读 contexts/A.md、B.md、C.md 写作
#    每组重复 3 次，输出到 articles/{A,B,C}-r{1,2,3}.md

# 4. 判分
python e2e_article/score_multi.py
```

手工复跑单个会话时，把上下文包全文贴给新会话即可；包里已写清素材路径和输出路径。

## 六、成果分析

### 核心数据（N=3，均值 ± 总体标准差）

| 指标 | A 未接入 | B 接入 ASC | C 等量无治理 |
|---|---:|---:|---:|
| 通过项 / 11 | 8.3 ± 0.5 | **10.7 ± 0.5** | 9.3 ± 0.5 |
| 四主题一级标题数 | **0.0 ± 0.0** | **4.0 ± 0.0** | 0.0 ± 0.0 |
| 禁用内容类别数 | 1.7 ± 0.5 | **0.0 ± 0.0** | 0.3 ± 0.5 |
| 字数达标（2500–3500） | 1/3 | 3/3 | 2/3 |
| 反引号术语数 | 86.3 ± 11.1 | 86.7 ± 3.4 | 60.0 ± 10.7 |
| 中文字符数 | 2113 ± 473 | 2407 ± 264 | 2506 ± 116 |

### 结论

1. **格式约束是最稳定的差异。** B 组 3/3 把四个主题写成一级标题，A、C 两组 0/3。A 组有任务书但没状态卡，模型把主题写成二级标题或散文式段落；B 组状态卡把「一级标题只保留四个」作为硬约束注入，3 次全部命中。这是最有说服力的单点证据：差异不是模型更聪明，是约束以机器可读的形式进了上下文。

2. **治理拦住了素材里的真实旧值。** A 组 3 次里有 3 次命中禁用内容——`11 个工具`、公众号名里的编程语言名、`可用性`；B 组 0 次。这些词都在素材里真实存在，不是模型幻觉。旧值被 ASC 标为过期、从 lean 卡里移出，模型就没机会引用。

3. **B vs C 证明收益来自治理，不是来自信息量。** C 组拿到的讲解事实和 B 组等量（9.7k vs 10.0k 字符），但约束降为软约束、旧值并列注入，结果通过项掉到 9.3、四主题一级标题 0/4、有 1/3 命中禁用内容。等量信息下关掉治理就回退，因果链是干净的。

4. **字数达标率也跟着走。** A 组 1/3、B 组 3/3、C 组 2/3。硬约束里有「2500–3500 字」，B 组稳定达标；A 组有一次只有 1453 中文字，明显偏短。

5. **反引号稳定性提升。** B 组 86.7 ± 3.4，方差最小；A 组 86.3 ± 11.1，C 组 60.0 ± 10.7。B 组不是写得最多，而是每次都稳定写出术语。

### 边界（对外说明时必须一起说）

- **N=3，样本量小。** 只作方向性判断，不报显著性。
- **写作有随机性。** WorkBuddy 独立会话无法固定 temperature，同一包三次产物不同，这是观测到的方差来源。
- **机器判分只判可判定项。** 可读性、钩子质量、说服力不打分，最终用稿是人工从 B 组三篇里挑的。
- **单任务单领域。** 只测了中文技术推文写作，不能外推到代码修改、多轮问答或长任务。
- **收益是「约束遵循」而非「内容质量」。** B 组的优势在确定性的格式与事实边界，不证明文章本身比人写得好。

### 一句话对外表述

> 我拿同一个推文任务做了三组对照：不接状态服务，四个一级标题 3 次一次都没写对；接了之后 3 次全对，素材里的过期值一次都没引用。把治理关掉但给等量信息，立刻回退。说明我加的这层不是在给模型塞更多知识，是在决定「此刻哪些要求还有效、哪些值不能引用」。

## 七、口径说明

1. token 估算为中文字符数 + 非中文字符数除以 4，只用于相对比较，不作成本承诺。
2. 禁用内容里的旧值来自素材本身（过时的材料版本、旧的工具数量口径、含编程语言名的旧账号名），命中说明旧值没被治理层拦住。
3. 三组会话互相隔离，只读自己的上下文包与包里列出的素材文件。
